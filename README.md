# EE 641 Chess RL Project - Starter

This is **milestone 1**, not the finished chess bot. The project will investigate
whether a search-free neural chess policy can improve through supervised
initialization and PPO self-play.

## Setup (Windows Command Prompt)

Install **Python 3.11 or newer** and make sure `py` or `python` works in CMD.
Internet is required for the initial dependency installation.

Open CMD in this folder and run:

```cmd
run.cmd
```

This command creates `.venv`, installs `requirements.txt`, runs unit tests,
plays one random legal-move example game, and checks that the untrained neural
network outputs have the expected shapes. It prints whether PyTorch sees CUDA.
The first installation may take a while because PyTorch is a large dependency.

To run just a demonstration later:

```cmd
run.cmd demo
```

To check the neural model:

```cmd
run.cmd model
```

To rerun only tests without the demo:

```cmd
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

If you change `requirements.txt`, delete `.venv\.requirements_installed` and
run `run.cmd` again. If you want a clean environment, delete `.venv`.

**GPU note:** Running milestone 1 doesn't require a GPU. PyTorch may initially
install without CUDA support. If `CUDA available` prints `False` on a machine
with an NVIDIA GPU, use the official PyTorch selector to install the correct
CUDA build: https://pytorch.org/get-started/locally/ . We'll verify GPU setup
before the actual neural training milestone.

## Current files

- `run.cmd`: one-command Windows setup and first run.
- `requirements.txt`: Python libraries.
- `chess_rl/environment.py`: chess moves, endings, and separate truncations.
- `chess_rl/encoding.py`: 61-plane board features and 4,672 move IDs.
- `chess_rl/network.py`: custom ResNet policy and value heads (untrained).
- `chess_rl/checkpoints.py`: permanent checkpoints at versions 0, 10, 20, etc.
- `chess_rl/main.py`: sample game and neural shape check.
- `tests/`: chess rules, move-encoding, network, and archive tests.
- `outputs/`: sample PGN and JSON generated by `run.cmd`.

## Chess rules

- Real checkmate/draw rules come from `python-chess`.
- Threefold repetition and fifty-move draws are **automatically claimed** in
  this training environment; this is a simplifying policy decision.
- Reaching the training `max_plies` limit does NOT mean the game is a draw.
  The environment returns `truncated=True` and `result='*'`.
- `terminal_reward(color)` yields +1/0/-1 for completed games only.
- The neural network does **not** use minimax, MCTS, Stockfish, or lookahead.
  Legal action masking is not search.

## Next milestones

1. Stream and preprocess downloaded Lichess PGN games; keep game-level
   train/validation/test splits and document rating/time-control filters.
2. Train the policy on human moves and value head on observed game outcomes.
   Record train/validation loss, move accuracy, and computer usage. Save V0.
3. Implement PPO and self-play against a mix of current and frozen checkpoints;
   save permanent versions every ten updates.
4. Build paired-color, fixed-opening tournaments against checkpoints and
   independent opponents; track score, draw reasons, Elo uncertainty, and
   learning curves. Include a search-based evaluation baseline **only**.
5. Run controlled opponent-pool and policy-stability ablations with multiple
   seeds; analyze failures and document compute cost.

## Data and trained weights

There are no bundled datasets or trained models. Raw PGNs belong under `data/`.
Checkpoint weights are written under `checkpoints/`. Both are ignored by Git.
This matches the EE 641 requirement to keep large training data and trained
weights out of the submitted code repository.
