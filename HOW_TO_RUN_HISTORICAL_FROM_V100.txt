STEP 1: VERIFY ON YOUR PC
  run.cmd ppo-historical-smoke

This checks the source checkpoint, original V0..V100 frozen opponents, game
sampling and actual small CPU/CUDA PPO update. Smoke changes weights only in
memory; it saves no model files or experiment logs.

STEP 2: TRAIN
  run.cmd ppo-historical-600k

Expected start:
  Historical-pool PPO, device=cuda, frozen V100 parent SHA256=...
  New step 1; target step 1149 (600,128 cumulative games).
  Opponent sampling per 512 games: 128 current, 256 recent archived,
  128 older archived. Colors paired; no search.

Training begins at 11,840 cumulative PPO games and performs 1,149 new
iterations of 512 games (588,288 additional games). This run uses the
original V100 model and optimizer state. Only new learner weights are updated;
all opponents are frozen. The training objective is unchanged and no chess
engine is used to train the model or choose moves.

Opponent pool initially contains ONLY original V0, V10, V20, ... V100.
NO original S49 / 50K / 75K / 100K or later latest-only model can appear in
this branch's opponent pool. Each ten iterations, a new historical branch
checkpoint enters the pool for future games.

The deterministic opening-position and PPO seeds match the current-only
V100->S49 experiment in its first 49 steps, then the S49->600K continuation
in later steps. Because PPO rollout batching and opponent choices differ,
results are NOT bit-for-bit matched; the comparison is experimental.

RESEARCH NOTE
The current-only baseline originally used serial rollout for its first 49
V100 continuation iterations and batched rollout afterward. The historical
branch uses the batched engine from the beginning. This difference matters
for interpreting strict causal claims. Both branches start from the same
V100 model and optimizer state, but neither is guaranteed to outperform the
other. For a rigorous ablation, repeat the current-only path with the same
batched rollout implementation and multiple seeds when time permits.
