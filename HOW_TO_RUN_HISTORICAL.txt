EE 641 | Historical-checkpoint PPO continuation from frozen 100K

PURPOSE
This is the original planned historical-opponent experiment, NOT the
existing current-only training branch. It starts from the same frozen
100,416-game model/optimizer state saved as s0124.pt.

BEFORE INSTALLING
- If run.cmd ppo-continue-600k is still training, end it with Ctrl+C.
  Each completed step saves to checkpoints\ppo_batch_continue\latest.pt.
  The previous saved step is preserved even if interrupted mid-iteration.
- Do not run both training processes at the same time on one GPU.
- Back up your current run.cmd, then extract this ZIP into:
  B:\EE641_Chess_RL_Starter
- Replace run.cmd if prompted. Add the two new chess_rl Python modules
  and one new test file.
- DO NOT replace, delete, or move checkpoints, data, outputs, benchmarks,
  the existing .venv, or the earlier PPO continuation module.

RUN THIS FIRST
run.cmd ppo-historical-smoke

This checks seven CPU-side unit tests and runs 8 short CUDA games (if CUDA
is available) with actual frozen historical opponents. It trains only in
memory and does not save any checkpoints or research outputs.

THEN RUN
run.cmd ppo-historical-600k

EXPECTED INITIAL OUTPUT
Historical-pool PPO, device=cuda, frozen 100K parent SHA256=...
New step 1; target step 976 (600,128 cumulative games).
Opponent sampling per 512 games: 128 current, 256 recent archived,
128 older archived. Colors paired; no search.

This is a NEW branch that always starts at 100,416 total PPO games,
regardless of whether your current-only experiment is at 120K, 200K,
or 600K. Its own step 1 is the first new 512 games after 100K.

TRAINING METHOD
- Current learner and fixed historical opponents are all search-free.
- 25% games against frozen current model, 50% vs recent archived ancestors,
  25% vs older ancestors; each opening is paired with both colors.
- At the start of each step, the recent list includes the previous 50K,
  75K and S49 lineage checkpoints. As new branch archives are saved every
  10 steps, it moves to the latest five branch archives.
- Older candidates include the original V0/V10/.../V100 plus other
  earlier ancestors; sample five candidates each step for diversity.
- Fixed checkpoint weights never change, and all opponent selections
  are recorded in outputs\ppo_historical_100k_opponents.csv.
- Uses original human opening manifest, 512 games/iteration, 240-ply cutoff,
  2 PPO epochs, minibatch 64, lr=1e-5, the same reward and GAE.
- Matches the original current-only continuation's opening/optimization
  seeds for global steps 125 onward; changing opponents changes RNG
  consumption, so runs are not bit-for-bit trajectory matches.

CHECKPOINTS AND RESUME
- New resumable checkpoint after EVERY 512-game step:
  checkpoints\ppo_historical_100k\latest.pt
- Permanent branch snapshots every 10 steps and at the milestone targets:
  s0195.pt -> 200,256 total games
  s0390.pt -> 300,096
  s0585.pt -> 399,936
  s0780.pt -> 499,776
  s0976.pt -> 600,128
- Earlier original current-only archives (s0026, s0075, s0124) and
  all October results remain untouched.
- Interrupted? Run the exact same command again. It resumes from the last
  completed saved historical step, not step 1.

several different models. Benchmark a few real iterations before estimating
any full-run runtime.
